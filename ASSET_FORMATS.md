# Asset Formats

Confidence levels: **Confirmed** means verified against the reference client by a passing test. **High** means consistent community documentation that has not yet been exercised by a test. **Unknown** is stated explicitly.

All integers are little-endian.

## GRF archive (Confirmed for 0x300, High for 0x200)

Implementation: `06_Godot_Project/scripts/resources/grf/grf_archive.gd`

### Header (46 bytes)

| Offset | 0x200 | 0x300 |
|---|---|---|
| 0 | char[16] signature (`Master of Magic`) | char[16] signature (kRO 2025: `Event Horizon\0c\0`) |
| 16 | byte[14] key (unused when not encrypted) | same |
| 30 | u32 table offset | **u64** table offset |
| 34 | u32 seed | (upper half of the u64 offset) |
| 38 | u32 count, where files = count − seed − 7 | u32 file count (exact) |
| 42 | u32 version | u32 version |

### File table at `table_offset + 46`

- 0x300 only: a leading u32. It is 0 in the reference client and its purpose is **unknown**.
- u32 compressed size, u32 uncompressed size, then a zlib stream.

### Entry

`name\0` (CP949 bytes), u32 compressed size, u32 aligned size, u32 real size, u8 flags, then the offset: u32 for 0x200, **u64** for 0x300. The offset is relative to byte 46.

Flags: `0x01` = file (0 = directory); `0x02` = mixed DES encryption; `0x04` = DES on the first 0x14 bytes only. **DES is not implemented yet.** The reference archive has no encrypted entries.

File data is a zlib stream of `compressed size` bytes.

**Evidence:** the header bytes of `data.grf`, a full table parse whose entry count matches the header (261,389), and decompressed `prontera.gat` beginning with `GRAT`.

### Names

Names are CP949 (Korean). The index stores them as lossless Latin-1 strings and lower-cases them for lookup. Folding produced 0 collisions across the reference archive (a test asserts this). `Cp949` (`scripts/resources/text/cp949.gd`) converts between the two using a table generated by `tools/gen_cp949_table.py`.

## SPR sprite sheet (Confirmed for 0x201)

Implementation: `scripts/resources/formats/spr_file.gd`

- `"SP"`, u8 minor, u8 major, u16 indexed frame count, plus u16 RGBA frame count if the version is ≥ 0x200.
- **Indexed frames:** u16 width, u16 height. For ≥ 0x201 this is followed by a u16 encoded size and RLE data: `0x00 n` means n transparent pixels (n = 0 is treated as 1), and any other byte is a literal. Older versions store w×h raw bytes.
- **RGBA frames:** u16 width, u16 height, then w×h×4 bytes in byte order **A, B, G, R**. Rows are stored **bottom-up**.
- **Palette** (≥ 0x101): the final 1,024 bytes, 256 × (R, G, B, unused). Index 0 is transparent.
- **Observed versions** (1/97 sample of the reference GRF): 0x201 only.

## ACT animation (Confirmed for 0x201, 0x203, 0x204, 0x205)

Implementation: `scripts/resources/formats/act_file.gd`

- Header: `"AC"`, u16 version, u16 action count, 10 reserved bytes.
- **Action:** u32 frame count, then that many frames.
- **Frame:** 32 bytes (two unused rectangles), u32 layer count, then the layers.
- **Layer:** i32 x, i32 y, i32 sprite index (−1 = none), i32 mirror flag. For ≥ 0x200 it continues: u8 R, G, B, A tint; scale (f32 x and f32 y for ≥ 0x204, a single f32 otherwise); i32 rotation in degrees; i32 image type (0 = indexed, 1 = RGBA). For ≥ 0x205 it adds i32 width and i32 height.
- **After the layers:** i32 sound event index for ≥ 0x200 (−1 = none). For ≥ 0x203: u32 anchor count, then per anchor 4 unknown bytes, i32 x, i32 y and 4 unknown bytes. Anchors attach heads and headgear to bodies.
- **Trailer:** u32 event count followed by 40-byte names for ≥ 0x201. For ≥ 0x202, an f32 per action giving the frame interval in **25 ms units**.
- Character and monster actions come in groups of 8 directions: `action = group * 8 + direction`. Poring has 72 actions (9 groups) and the Novice body has 104 (13 groups).

## Map formats: overview

Versions observed in the reference client: GAT 1.2 (908) and 1.3 (223); GND 1.7 (897), 1.8 (13) and 1.9 (194); RSW 1.9 (2), 2.1 (815), 2.2 (57), 2.3 (2), 2.4 (7), 2.5 (25), 2.6 (110) and 2.7 (113).

All 3,366 map files decode completely, including every RSW object table (integration test `test_all_maps_decode`).

## GAT altitude/attribute grid (Confirmed for 1.2 and 1.3)

Implementation: `scripts/resources/formats/gat_file.gd`

- Header: `"GRAT"`, u8 major, u8 minor, u32 width, u32 height.
- Cells: width × height records of 20 bytes each: f32 heights for the SW, SE, NW and NE corners, then a u32 type.
- Types: 0 = walkable, 1 = blocked, 3 = walkable water, 5 = blocked but snipeable. Heights grow **downward** (negative = higher).
- GAT is exactly twice GND's resolution (prontera: 312×392 GAT vs 156×196 GND, which is tested). One GAT cell is 5 world units.

## GND ground mesh (Confirmed for 1.7, 1.8 and 1.9)

Implementation: `scripts/resources/formats/gnd_file.gd`. Rendering: `scripts/rendering/map/ground_mesh_builder.gd`.

- **Header:** `"GRGN"`, u8 major, u8 minor, u32 width, u32 height, f32 zoom (cube size; 10), u32 texture count, u32 name length (80), then the texture names (CP949, relative to `data\texture\`).
- **Lightmaps:** u32 count, u32 px (8), u32 py (8), u32 cells (1). Each lightmap is px×py×4 bytes: 64 shadow-intensity bytes followed by 64 RGB colour triplets.
- **Surfaces:** u32 count, then **40 bytes** each: f32 u[4], f32 v[4], i16 texture, u16 lightmap, then u8 **B, G, R, A** tile colour. *(Correction to a common assumption of 56 bytes; confirmed because the cube section then ends exactly at end-of-file.)*
- **Cubes:** width × height records of 28 bytes: f32 heights for SW, SE, NW and NE, then i32 top, i32 front (wall to the cube at y+1) and i32 right (wall to the cube at x+1). −1 means none.
- **1.8 and later**, after the cubes: water as f32 level, i32 type, f32 wave height, f32 wave speed, f32 wave pitch, i32 animation speed, i32 split_w, i32 split_h. Then **1.8** stores split_w×split_h f32 levels, while **1.9** stores split_w×split_h full 24-byte water records. The byte counts match exactly (36 and 56 trailing bytes on the samples).

### Rendering model (High confidence, visually verified on prontera, prt_fild08 and izlude)

- Colour is computed as `texture × tile colour × clamp(ambient × opacity + diffuse × N·L) × shadow + lightmap RGB`, evaluated in sRGB space and converted to linear on output.
- Ground normals are **smoothed** per grid vertex, by averaging the up-to-four adjacent top faces. Flat shading shows obvious facets on slopes.
- Lightmap tiles have a 1-texel border, so the UVs sample texels 1–7 of each 8×8 tile.
- Godot mapping: x → x, height → −h, cell y → −z (north = −Z).

## RSW world descriptor (Confirmed for the object table, all versions present)

Implementation: `scripts/resources/formats/rsw_file.gd`

- **Header:** `"GRSW"`, u8 major, u8 minor. **2.2 and later** add a u8 build number; **2.5 and later** add another u32 (unknown). These are confirmed by the offsets of the `.gnd` name.
- **Strings:** char[40] each for the ini, gnd, gat and source names.
- **Water** (versions **below 2.6** only; from 2.6 water lives in GND 1.8+): f32 level, i32 type, f32 wave height, f32 wave speed, f32 wave pitch, i32 animation speed.
- **Light:** i32 longitude, i32 latitude, f32 diffuse[3], f32 ambient[3], f32 opacity. Then the ground bounds as i32 × 4.
- **2.7 and later:** u32 n followed by n×4 bytes (n = 16 in every map; purpose unknown).
- **Objects:** u32 count, then per object an i32 type followed by its record:
  - **1 = model:** char[40] name, i32 animation type, f32 animation speed, i32 block type, [u8], [**2.7: f32**, often −1.0], char[80] file, char[80] node, f32 position[3], rotation[3], scale[3].
    - The u8 is present in all 2.7 files and in 2.6 from build 162, plus builds 8 and 18. Those last two are probably the u8 build counter wrapping past 255 (Medium confidence).
    - *Correction:* the 2.7 f32 comes **before** the filename, not after the scale. Confirmed because every RSM2 model on 2.7 maps such as `mu_fild02` and `kindlbrk` now resolves and loads.
  - **2 = light:** 108 bytes.
  - **3 = sound:** 192 bytes.
  - **4 = effect:** 116 bytes.
- **Light direction:** longitude/latitude are converted to a vector. With a latitude of 45 the top-face N·L is the same whatever the longitude convention. The exact sign convention is Medium confidence.

## RSM / RSM2 models (Confirmed for 1.4, 1.5, 2.2, 2.3; 2.0/2.1 unsupported)

Implementation: `scripts/resources/formats/rsm_file.gd`. Baking: `scripts/rendering/map/rsm_mesh_builder.gd`.

Versions in the reference client: 1.4 (6,588), 1.5 (490), 2.1 (2, `engine/biggear*`), 2.2 (448) and 2.3 (2,098).

### Header

- `"GRSM"`, u8 major, u8 minor, i32 animation length, i32 shade type (0 none, 1 flat, 2 smooth), then u8 alpha for ≥ 1.4.
- **1.x:** 16 reserved bytes, i32 n + n × char[40] textures, char[40] root name, i32 node count.
- **2.x:** f32 fps, [**2.2 only:** i32 n + n length-prefixed texture names], i32 n + n length-prefixed root names, i32 node count.

### Node

- Name and parent name: char[40] in 1.x, length-prefixed strings in 2.x.
- Texture references: i32 n, then i32 indices into the global list (1.x and 2.2) or length-prefixed names (2.3).
- f32 offset[9] (3×3, column-major), then f32 position[3].
- **1.x only:** f32 translation[3], f32 rotation angle (radians), f32 rotation axis[3], f32 scale[3].
- Vertices: i32 n + n × f32[3].
- Texture coordinates: i32 n + n × ([u32 colour if ≥ 1.2], f32 u, f32 v).
- Faces: i32 n + n × ([**2.x:** i32 record length], u16 v[3], u16 t[3], u16 texture, u16 pad, i32 two-sided, [i32 smoothing group if ≥ 1.2]).
- Keyframes: [≥ 1.6: scale keys, 20 bytes each], rotation keys (i32 frame + quaternion xyzw), [≥ 2.2: position keys, 20 bytes each], [≥ 2.3: texture animations].
- A few trailing bytes (volume boxes) follow the last node.

### Baking (RO space, y down)

- **1.x** (High confidence; visually verified on prontera, izlude and prt_fild08):
  - `node_world = parent * T(translation) * R(first rotation key, or angle/axis) * S(scale)`
  - `v' = centre * node_world * T(position) [skipped for single-node models] * offset * v`
  - `centre = T(−bbox.center.x, −bbox.max.y, −bbox.center.z)`, so models stand on y = 0.
- **2.x** (Medium confidence; looks plausible on mu_fild02 and kindlbrk):
  - `node_world = parent * T(first position key, or position) * R(rotation key) * S(scale key)`
  - `v' = node_world * offset * v`, with no centring.
- **Instances** (from RSW): `T(pos + map half-extent) * Rz * Rx * Ry * S`, with RSW rotation in degrees. RO space is then converted to Godot by `diag(1, −1, −1)`, which is a proper rotation. The map orientation is confirmed: Prontera's church appears in the northeast.
- **Shading:** `texture × clamp(ambient + diffuse × N·L)`. Smooth-shaded models average normals per vertex and smoothing group. Magenta texels are discarded.
